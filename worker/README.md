# 下载计数（Cloudflare Worker + D1）

统计官网各版本被下载了多少次，结果呈现在 <https://times.sfw.us.ci>。

站点本身是纯静态的（GitHub Pages），下载按钮直连 GitHub Releases，**服务器端看不到点击**。
所以只能由前端在点击瞬间上报版本号。

```
sfw.us.ci 任意页面
    │  点下载按钮 → navigator.sendBeacon
    ▼
times.sfw.us.ci/api/hit       ← Cloudflare Worker
    │  当天该版本 +1
    ▼
D1 数据库  daily(version, day, count)
    │
    ▼
times.sfw.us.ci/              ← 统计页面（同一个 Worker 渲染）
```

---

## 一、为什么按「版本 + 日期」存，而不是每次下载一行

存成 `(version, day, count)` 之后：

- 行数 = 版本数 × 天数。5 个版本跑一年也就 1800 行左右
- 「总下载」「各版本排行」「每日趋势」三种查询都能直接出
- 写入量还是「一次点击一次写」，和逐条存一样

如果只存一个总数字，就再也查不出「哪天开始涨的」。

## 二、部署步骤

### 1. 建 D1 数据库

Cloudflare 控制台 → 左侧 **「存储和数据库」** → **「D1 SQL 数据库」** → 右上角 **「创建数据库」**

- 名称随便填，比如 `sfw-downloads`
- 创建完**进入这个库**，再打开 **「控制台」** 选项卡（英文界面里叫 Console 或 Query）

然后**一条一条执行**，每贴一条点一次右侧 **「执行」**：

**第 1 条 · 建表**

```
CREATE TABLE IF NOT EXISTS daily (version TEXT NOT NULL, day TEXT NOT NULL, count INTEGER NOT NULL DEFAULT 0, PRIMARY KEY (version, day));
```

**第 2 条 · 按日期查趋势的索引**

```
CREATE INDEX IF NOT EXISTS idx_daily_day ON daily (day);
```

**第 3 条 · 按版本汇总的索引**

```
CREATE INDEX IF NOT EXISTS idx_daily_version ON daily (version);
```

三条都成功后，概览页的「表数量」会从 0 变成 1，索引 2 个。

> **⚠️ 报 `incomplete input: SQLITE_ERROR` 怎么办**
>
> 这个错的意思是「SQL 语句没写完」—— 少了个右括号、或者只粘了一半，就会报它。
> **不是 SQL 写错了**：整份文件在本地用真实 SQLite 实测过，能正常建表和索引。
>
> 处理办法：**清空输入框，一次只粘一条**再执行。上面三条都是单行的，
> 复制时不容易走样；如果还不行，手打一遍那条也行（都不长）。
>
> 另外确认一下：你是**进入某个库之后**打开的「控制台」，
> 而不是在 D1 列表页直接点的 —— 没选中库时执行会报别的错。

> **⚠️ 更隐蔽的情况：执行不报错，但「表数量」一直是 0**
>
> 这个吃过一次。原因是**行注释**（两个减号开头的那种）：
> D1 的输入框把多行粘成一行之后，行注释会把那一整行后面**全部吃掉**，
> 连 `CREATE TABLE` 一起变成注释。SQLite 对空语句不报错，
> 所以界面显示执行成功、查询数也 +1，但表根本没建出来。
>
> 现在 `schema.sql` 里**一个行注释都没有**，说明文字全用块注释包着，
> 就是为了让压成一行也能正常执行。三种粘贴方式（原样 / 压成一行 / 只贴语句）
> 都实测过，都能正确建表。
>
> 万一还碰到：**只贴 `CREATE ...` 那一行，前后不要带任何两个减号开头的内容。**

### 2. 建 Worker

左侧 **「计算」** → **「Workers 和 Pages」** → **「创建应用程序」**（新版界面可能直接叫「创建」）
→ 选 **「从 Hello World 开始」** → 起个名字（比如 `sfw-download-counter`）→ **「部署」**

部署完点 **「编辑代码」**，把编辑器里的内容**整个删掉**，换成 `index.js` 的全部内容，然后再点 **「部署」**。

> 这个文件是 ES Module 格式（`export default { fetch }`）。新版编辑器会自动识别；
> 如果提示格式不对，去 **「设置」→「运行时」** 把兼容模式改成 **ES Module** 即可。

### 3. 绑定 D1

Worker 详情页 → **「设置」** → **「绑定」** → **「添加」** → 选 **「D1 数据库」**

| 项目 | 必须填成 |
|---|---|
| 变量名称 | **`DB`** |
| D1 数据库 | 第 1 步建的那个 |

⚠️ 变量名**必须是 `DB`**，代码里写死了 `env.DB`，填别的会直接报 500。
填完点 **「保存」**（有的界面是「保存并部署」）。

### 4. 绑自定义域名

Worker 详情页 → **「设置」** → **「域和路由」** → **「添加」** → 选 **「自定义域」**

填 `times.sfw.us.ci`，点确认。

因为 `sfw.us.ci` 的 DNS 就在 Cloudflare，它会自动加一条记录并签证书，**不用自己去 DNS 面板操作**。
等状态变成 **「有效」**（英文界面显示 Active，一般一两分钟）就好了。

### 5. 验证

浏览器打开 <https://times.sfw.us.ci>，应该看到一个空的统计页（显示 0）。

想确认数据库通了，直接访问 <https://times.sfw.us.ci/api/stats>，返回的 JSON 里 `total` 应该是 0。

再用命令行打一次测试数据：

```bash
curl -X POST https://times.sfw.us.ci/api/hit -d "{\"v\":\"1.1.3\"}"
```

刷新统计页，总下载应该变成 1。

> 记完这一次之后记得清掉：Cloudflare 控制台 → 「存储和数据库」→「D1 SQL 数据库」→ 你的库 →
> 「控制台」→ 执行 `DELETE FROM daily WHERE version='1.1.3';`

## 三、前端已经接好了

`src/layouts/BaseLayout.astro` 里有一段全局点击监听，**全站生效**。
它的规则很简单：**页面上任何 `<a>` 只要带 `data-dl-version` 属性，被点击时就上报那个版本号**。

已经标好的 6 处：

| 文件 | 位置 |
|---|---|
| `src/components/Nav.astro` | 右上角「立即下载」 |
| `src/pages/top.astro` | 首屏按钮 + 底部「下载 v1.1.3」 |
| `src/pages/index.astro` | 欢迎页最后一屏 |
| `src/pages/download.astro` | 「立即下载」 |
| `src/pages/history.astro` | 历史版本表格（每个文件各自带版本） |

**以后新加下载按钮**，只要记得写 `data-dl-version={site.version}`（历史版本用 `{r.version}`），
统计就会自动生效，不用动任何脚本。

### 几个刻意的设计

- **本地预览不上报**：`localhost`、`127.0.0.1`、`0.0.0.0`、`[::1]` 直接跳过，
  免得开发时的点击混进真实数据
- **用 `sendBeacon` 而不是 `fetch`**：前者专为「页面即将跳转」设计，请求不会因为导航被打断；
  老浏览器没有它时降级成 `fetch(..., { keepalive: true })`
- **整段包在 `try` 里**：统计是附加功能，出任何错都不能影响下载
- **每次点击都算**：你选的是不去重。想改成「同一天同版本只算一次」，
  可以在上报前用 `localStorage` 记一下当天报过哪些版本

## 四、想改页面

统计页是 `index.js` 里 `renderPage()` 生成的（一个函数吐整页 HTML，不需要构建）。
配色包括深色模式在 `<style>` 里，主色是 `--brand: #005a9e`，跟主站一致。

- 想多显示点内容：在 `collectStats()` 里加查询，在 `renderPage()` 里加区块
- 想改趋势天数：脚本开头的 `TREND_DAYS = 30`
- 想改时区：`TZ_OFFSET_MS = 8 * 3600 * 1000`（北京时间）

## 五、这些数据能扛多少量

Cloudflare 免费额度：

| 项目 | 免费额度 |
|---|---|
| Workers 请求 | 10 万次 / 天 |
| D1 行写入 | **10 万行 / 天**（一次下载 = 1 次写） |
| D1 行读取 | 500 万行 / 天 |
| D1 存储 | 5 GB（单库上限 500 MB） |

按每天 1000 次下载算，写入只用到 1%，读也远远用不完。

⚠️ 超了会怎样：D1 当天直接返回错误，直到 UTC 0 点重置，**不是**自动转成计费。

## 六、一个已知限制

**页面能被任何人访问**，包括 `/api/stats`（数据接口是公开的）。
页面加了 `<meta name="robots" content="noindex">`，搜索引擎不会收录，但知道地址的人能打开。

如果不想公开，有两个办法：

1. 给 Worker 加一个查询参数校验（只有带对 token 才返回数据）
2. 干脆不绑自定义域名，只用 `*.workers.dev` 的地址，自己看

需要的话说一声，改起来很快。
